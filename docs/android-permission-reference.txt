LAILABA DEVICE AGENT — ANDROID PERMISSION REFERENCE
Purpose: Reference list of permissions mentioned in the supplied Android manifest.

IMPORTANT NOTES
- This is a reference list, not a recommendation to request every permission.
- Declaring a permission does not automatically grant access.
- Some permissions are deprecated, restricted, privileged, signature-protected, role-limited, or unavailable to ordinary apps.
- Runtime permissions and special access may require user approval.
- Request only permissions needed for clearly disclosed, legitimate features. Respect user consent and Android/Google Play policies.
- This list does not provide full control of a device by itself.

IMPLEMENTATION NOTES
- Service-binding permissions are generally declared on the relevant service component using android:permission; they are not ordinary runtime permissions to request in the usual way.
- A VPN service normally declares android.permission.BIND_VPN_SERVICE on its service component and includes the android.net.VpnService intent action.
- Device-owner, system, signature, or privileged capabilities require the appropriate Android provisioning, signing, role, or system-level access; listing them here does not enable those capabilities.
- Ask users for clear, informed consent and provide a visible way to understand and disable optional access.
